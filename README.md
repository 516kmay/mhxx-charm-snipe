# MHXX Charm Snipe Tool

モンスターハンターダブルクロス（MHXX）の **お守りスナイプ（RNG操作）** を支援する Java Swing 製デスクトップツール。

お守り検索・乱数逆算・調合スナイプ・Arduino自動化コード生成・タイマー機能を1つのアプリに統合している。

---

## 動作環境

- Java 21 以上
- Switch版MHXX（実機RNG挙動に基づく）
- Arduino機能を使う場合: Arduino Leonardo + NintendoSwitchControlLibrary

## 起動方法

### Windows
```
run.bat
```
内部で `javac` ビルド → `java` 実行 を行う。初回はビルドのため少し時間がかかる。

### macOS / Linux
```
run.sh
```

## 全体ワークフロー

このツールは「**狙ったスキル・SP値・スロットを持つお守りを、特定のRNGフレームに到達することで意図的に出す**」という目的のために作られている。

典型的な利用フローは以下：

1. **お守り検索** で目的のお守りが出現するフレームを見つける
2. **周辺表示** で目標フレーム周辺の安全マージン（ロードブレ耐性）を確認
3. **キャリブレーション** で実機の消費フレーム値（c, fc）を実測
4. **調合スナイプ** または **Arduino** タブでスナイプ用のArduinoコードを生成
5. 実機で実行 → 録画確認
6. ズレがあれば **補正計算** で次回パラメータを再計算

---

## タブ別機能解説

### 1. お守り検索

目標のお守り条件（第1スキル・SP・第2スキル・SP・スロット数）を指定して、それを満たすフレームを総当たりで探索する。

**主な入力:**
- お守り種別（風化／古びた／光るお守り）
- 原産地（マカ錬金／クエスト炭鉱）
- カテゴリフィルタ（攻撃系・防御系・剣士用など）
- 第1スキル＋SP値、第2スキル＋SP値、スロット数
- 検索開始基準F＋検索フレーム数（基準Fの次から検索。デフォルトは基準0F・1,000,000F）
- 検索モード（完全一致／以上）

クエスト産では負の第2SPも選択できる。重複スキルと負側計算で0になった第2スキルは「なし」として扱う。

**出力:**
- 該当フレームのリスト（フレーム番号・スキル・SP・スロット・累計時間・レア度）
- 各行を右クリックで「Arduinoコード生成」が可能

### 2. 周辺表示

特定のフレーム位置を中心に、その前後 N フレームのお守り内容を一覧表示する。

「狙ったフレームでハズレを引いた時、隣のフレームが何だったか」を確認するのに使う。

**特殊なハイライト:**
- 中央フレーム → 強調色
- ±30F以内 → 「ロードブレ耐性圏内」として薄くハイライト

### 3. 調合スナイプ

「調合（アイテム生成）」の弾数列から `search_combo` 相当の調合基準F（調合開始位置に調合による追加消費を加えた値）を逆算し、目標フレームまでの進行を見積もる。表示する目標との差分は参考値であり、実際の待機には調合後の経過や操作時間を差し引く。

**入力:**
- 累積弾数（実機の調合録画から逆算）
- 検索開始F・検索フレーム数（既知の現在位置付近だけを再検索可能）
- 目標フレーム（お守り検索や有名お守りタブから連動）
- 調合回数の目安、Lv2弾までの↓キー数

**出力:**
- 調合スナイプ Arduino コード（録画用）
- 周辺フレームのお守り一覧（誤差耐性確認用）
- 候補行の右クリックから、目標Fまでの差を手動カウントダウンへ転送

### 4. 調合Arduino（2コード方式 + 予備コード3）

調合スナイプを **2段階のArduinoコード** で実装する。HOME中断中は乱数が停止する仕様を利用。長時間待機が必要なときは予備のコード3で再調合できる。

**ワークフロー:**
1. **コード1** → Continue連打（500ms周期）→ ロード前待機 → 自宅へ移動 → 必要ならプーギーを屋外へ退避 → アイテムボックス前で調合（約4秒A長押し）→ 30秒録画 → HOME中断
2. 録画から累積弾数を読み、調合基準Fを逆算。Switchのアルバムからの録画転送は手動で行う。
3. **測定用コード2**（待機0）で錬金確定フレームを実測し、`オフセットF = 実測F − 調合基準F` を設定。同じコード1の手順・接続方法で測定する。
4. **コード2** → HOME復帰 → 自宅のアイテムボックス前で待機 → アイシャ前へ歩いて移動 → ルームサービス経由のマカ錬金 → ケルビ納品 → 鑑定

**予備コード3**はコード1後のHOME中断から再開し、指定時間だけアイテムボックス前で待機してから、登録済みのアイテムマイセットを呼び出して所持品を復元する。その後はコード1と同一の調合・録画・HOME操作を生成する。新しい録画から調合基準Fを再特定し、コード2の待機を再計算する。古い調合基準Fとコード2の待機時間は引き継がない。コード3に入力する箱メニュー位置、呼び出しメニュー位置、マイセット番号、確認A回数は実機の画面に合わせる。マイセット選択画面が直接開く場合は「呼出↓」を `-1` にして中間のA入力を省く。補充用素材と調合書を含み、Lv2通常弾が0個のマイセットを事前に登録しておく。

コード2の待機は `(目標F − 調合基準F − オフセットF) ÷ 30 × 1000` ms。オフセットは調合後の経過とコード2の操作時間を含む実測値で、未測定のまま本番コード2を生成しない。コード1の手順・移動・接続方法を変えたら再測定する。長時間待機する場合はSwitchの自動スリープを無効にする。マイコンが再認識されない場合は、Switchで「コントローラー → 持ち方/順番を変える」を開き、コード2のL+R再接続オプションを使う。出入口、メニュー選択、移動距離は実機で確認・調整が必要。

参考: [2コード方式と予備の3つ目のコード](https://note.com/lovely_rabbit863/n/n7679210d39b2)、[search_combo の出力仕様](https://github.com/apmnnn/mhxx-rng/blob/main/docs/functions.md)、[カプコン公式マニュアルのアイテムマイセット説明](https://game.capcom.com/manual/MHXX/page/14/4)。記事にはマイセットの具体的なボタン列は掲載されていないため、生成された操作列は実機で確認・調整する。

**入力フィールド:**
- Continue回数（コード1）
- ロード前待機ms、プーギー退避の有無（コード1）
- Lv2弾までの↓数
- 調合基準F、実測オフセットF、再接続の有無（コード2）
- 再調合前待機ms、マイセットのメニュー位置・番号・確認A回数（コード3）
- 目標F（調合スナイプタブと双方向連動）

### 5. タイマー

#### ラップタイマー
- スペースキーで開始／ラップ記録
- Enterキーで停止＆記録
- Rキーでリセット
- ラップタイム・累計時間・フレーム換算を表示
- CSV保存対応

#### 目標時間設定
- 目標フレーム・基準フレームから所要時間を計算

#### マカ錬金カウントダウン（手動投入用）
Arduinoを使わず手動でマカ錬金のタイミングを取りたい時のカウントダウン機能。

- **待機時間 (ms)**: 待ちたい時間（調合スナイプの wait_ms をコピペ可）
- **開始までの猶予 (秒)**: 準備時間
- **切り上げ (秒)**: 投入を少し早める時間
- **サウンド有効**: チェック時、残り10秒からビープ、終了時に強い音

### 6. Arduino（Continue連打法）

タイトル画面でContinue→キャンセルを連打して RNG を進めるシンプルな手法。調合スナイプより手軽だが、目標Fが大きい場合は時間がかかる。

**入力:**
- 目標フレーム
- 基本消費フレーム c（デフォルト 1,675）
- Continue1回の消費フレーム fc（デフォルト 714）
- 待機時間の範囲（5,000〜20,000ms など）

**出力:**
- 計算結果: Continue連打回数、端数待機ms、推定到達F、総所要時間
- Arduino スケッチ（コピー or `.ino` 保存）

#### 待機時間の補正
実測フレームと目標フレームのズレから、次回用の Continue回数 と 待機時間 を再計算する。

実機の実測値から fc_actual を逆算し、前回 nc 近傍で探索して、最も差分が小さい解を採用する設計。

**入力:**
- 目標フレーム、実測フレーム、Continue回数、前回の待機時間

**出力:**
- ズレ量（オーバー／不足）
- 補正後パラメータ（Continue回数、待機時間）
- 補正ログテーブル（CSV保存可）

### 7. 報酬逆算

クエスト報酬画面に表示されたアイテムの個数と並びから、現在のフレームを特定する。

調合スナイプでズレた時、「どのフレームで終わったのか」を逆算するのに使う。

**入力:**
- 報酬個数（4〜8個）
- 報酬アイテムリスト（複数可）
- 検索開始F・検索フレーム数
- 追加報酬閾値（なし=22、幸運=25、強運=28、激運=31）

**出力:**
- 報酬生成直前F
- 報酬生成による消費（4〜8個に対して5/7/9/11/12F）を加えた現在F
- 現在F時点のクエスト産お守り

### 8. クエスト周回

特定のクエスト報酬パターンを利用したRNG消費＋逆算ワークフロー用。

### 9. キャリブレーション

実機の消費フレーム値（c, fc）を実測するための補助タブ。

### 10. 有名お守り

実用性の高い「有名な良お守り」のリストとそのフレーム位置を確認できる。

## 設定の保存

ウィンドウを閉じる時に、実行ディレクトリの `mhxx_charm_settings.properties` に各種入力値が自動保存される。次回起動時に復元される。

**保存対象:**
- お守り検索: 種別・スロット・検索開始F・検索範囲・選択スキル・SP値
- 周辺表示: フレーム位置・原産地・前後範囲
- 報酬逆算: 検索開始F・検索範囲・追加報酬閾値
- 調合スナイプ: 累積弾数・検索開始F・検索範囲・目標F・Continue回数・調合回数・Lv2↓数
- 調合Arduino: 現在F・目標F（調合スナイプの目標Fと連動）
- 待機時間の補正: 目標F・実測F・Continue回数・前回の待機時間
- Arduino: c・fc・目標F
- ウィンドウ位置・サイズ
- 選択中タブ

## 補正計算ロジック（技術的補足）

ツールが目標到達するフレームを計算する基本式：

```
actual_frame = c + fc × nc + 0.030 × t2
```

- `c`: 基本消費フレーム（固定）
- `fc`: Continue1回あたりの消費フレーム
- `nc`: Continue連打回数
- `t2`: 端数待機時間（ms）
- `0.030`: 1msあたり0.03フレーム（30fps）

実機との誤差が出た場合、`fc_actual` を逆算してから再計算する：

```
fc_actual = (actual - c - 0.030 × prevT2) / prevNc
```

これを使って前回 `nc` 近傍から探索し、最小変更で目標到達できる解を採用する。
