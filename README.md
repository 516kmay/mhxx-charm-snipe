# MHXX Charm Snipe Tool

モンスターハンターダブルクロス（MHXX）の **お守りスナイプ（RNG操作）** を支援する Java Swing 製デスクトップツール。

お守り検索・乱数逆算・調合スナイプ・Arduino自動化コード生成・タイマー機能を1つのアプリに統合している。

---

## 動作環境

- Java 21 以上（WindowsのOracle JDK 27でも動作確認済み）
- Switch版MHXX（実機RNG挙動に基づく）
- Arduino機能を使う場合: Arduino Leonardo + NintendoSwitchControlLibrary

## 起動方法

### Release ZIP

ZIPを展開してから起動する。Java 21以上の実行環境が必要。

- Windows: `start.bat` をダブルクリック
- macOS / Linux: 展開先で `java -jar MHXX-Charm-Snipe.jar` を実行

### ソースから起動（JDK 21以上）

Windows:
```
run.bat
```
内部で `javac` ビルド → `java` 実行 を行う。初回はビルドのため少し時間がかかる。

JDK 27でも、既存の `--release 21` 設定のままビルドできる。WindowsのOracle JDK 27で、ビルド・回帰テスト168項目・v0.4.6の配布JARの起動を確認済み。

macOS / Linux:
```
run.sh
```

## 全体ワークフロー

このツールは「**狙ったスキル・SP値・スロットを持つお守りを、特定のRNGフレームに到達することで意図的に出す**」という目的のために作られている。

典型的な利用フローは以下：

1. **お守り検索** で目的のお守りが出現するフレームを見つける
2. **周辺表示** で錬金方式・投入ポイントに合う「錬金確定F」の候補を確認
3. **調合Arduino** でContinue回数を概算してコード1を実行し、調合を録画
4. 外部の調合フレーム特定ツールで録画を解析し、表示された調合開始Fを**調合Arduino**に入力
5. コード2で投入確認画面まで進み、目標時刻に確定。初回は着弾補正F=0で進め、ずれた場合だけ補正

---

## タブ別機能解説

### 1. お守り検索

目標のお守り条件（第1スキル・SP・第2スキル・SP・スロット数）を指定して、それを満たすフレームを総当たりで探索する。

**主な入力:**
- お守り種別（風化／古びた／光るお守り）
- 原産地（マカ錬金／クエスト炭鉱）
- カテゴリフィルタ（攻撃系・防御系・剣士用など）
- 第1スキル＋SP値、第2スキル＋SP値、スロット数
- 検索開始基準F＋検索フレーム数（基準Fの次から検索。デフォルトは基準0F・1,000,000F）
- 検索モード（完全一致／以上）

クエスト産では負の第2SPも選択できる。重複スキルと負側計算で0になった第2スキルは「なし」として扱う。

**出力:**
- 該当フレームのリスト（フレーム番号・スキル・SP・スロット・累計時間・レア度）
- 各行を右クリックして周辺表示やArduinoコード生成へ進める

### 2. 周辺表示

特定のフレーム位置を中心に、その前後 N フレームのお守り内容を一覧表示する。

「狙ったフレームでハズレを引いた時、隣のフレームが何だったか」を確認するのに使う。お守りの生成Fと、錬金を確定するFは一致するとは限らない。

マカ錬金の孤立判定では、**お守り種別・マカフシギ/天運・投入合計pt**を選ぶと、ランク1～4を算出し、そのレシピで最初の錬金セットから目標のお守りが出る投入候補Fを全件表示する。候補0点は「そのレシピ・ランクでは狙えない」という意味で、別方式や投入ptを試す。クエスト産は従来どおり連続ヒット数で判定する。

調合スナイプと調合Arduinoの目標Fには、この**投入候補F**の中から狙う値を使う。周辺表示の「投入候補Fを調合Arduinoへ」で転送できる。検索結果や有名お守り一覧のFは「お守り生成F」で、直接の錬金確定Fとは限らない。

投入するお守りは兵士/闘士=1pt、騎士/城塞=2pt、女王/王/龍=3pt。天運のランクは3pt→1、4～5pt→2、6～7pt→3、8～9pt→4。マカフシギは3～4pt→1、5pt→2、6～8pt→3、9pt→4。ランクを下げた方が狙い目が増える場合もある。投入順を固定するため、アイテムBOXの「装備の変更・売却」→「入れ替える」で素材のお守りを並べ、錬金の選択画面ではXを5回押して「登録順」にする。入手した大事なお守りは素材として再投入しないよう保護する。

例: 光る「野草知識1 強撃弾追加12 S2」の生成位置12747Fは天運rank4で投入候補8点（12733F、12741Fなど）。古びた「溜め短縮2 雷耐性13 S3」の生成位置3526870Fは、マカフシギrank4では候補0点、rank3なら3526864F、天運rank4なら3526870Fで狙える。

**特殊なハイライト:**
- 中央フレーム → 強調色
- ±30F以内 → 周辺比較用に薄くハイライト。**当たりの保証ではない**（投入候補Fを確認する）

### 3. 調合スナイプ

「調合（アイテム生成）」の弾数列から `search_combo` 相当の調合開始Fを逆算し、目標フレームまでの進行を見積もる。表示する目標との差分は参考値。コード2では調合開始からHOMEまでの時間を差し引き、復帰後の移動・メニュー操作も投入時刻の計測に含める。

**入力:**
- 累積弾数（実機の調合録画から逆算）
- 検索開始F・検索フレーム数（既知の現在位置付近だけを再検索可能）
- 目標投入F（周辺表示で確認した錬金確定F。調合Arduinoと連動）
- 調合回数の目安、Lv2弾までの↓キー数

**出力:**
- 調合スナイプ Arduino コード（録画用）
- 周辺フレームのお守り一覧（誤差耐性確認用）
- 逆算結果の選択行から調合開始Fを調合Arduinoへ転送
- 候補行の右クリックから、目標Fまでの差を手動カウントダウンへ転送

### 4. 調合Arduino（Continue → 調合で現在F確認 → 目標時刻に投入）

目標投入Fを入力するだけでContinue回数の**初回目安**を計算できる。キャリブレーションで「調合Arduino（500ms周期）」のContinue消費を計算すると、回数概算へ自動反映される。主画面に使用中の1回消費Fと校正済みかを表示し、未校正時は717F/回を使う。調合開始Fは外部ツールの解析結果を入力でき、内蔵の調合スナイプとの連携は必須ではない。実機設定と任意の着弾補正は必要なときだけ展開する。HOME中断中は乱数が停止する仕様を利用する。

**ワークフロー:**
1. 周辺表示で使用する錬金方式・投入ptの**投入候補F**を選び、調合Arduinoへ転送。ココット村でセーブして開始する。
2. 「Continue回数を概算」→**コード1**を生成・実行。500ms周期でContinue連打後、自宅で調合して30秒録画し、HOMEで中断する。Lv2弾の位置・ロード前待機・プーギー退避は詳細設定で調整できる。
3. 外部の調合フレーム特定ツールで録画を解析し、表示された**調合開始時点のF**を調合Arduinoに入力する。HOME中断時の現在Fへ換算せず、そのまま入力する。コード1の調合開始からHOMEまでの時間はアプリが差し引く。
4. **コード2**を生成・実行。初回の着弾補正Fは0のままでよい。HOME復帰前にYを3回入力し、その後のHOME復帰から時刻を計測する。ルームサービスのメニューを下3回→A2回で選び、護石3個を選択して投入確認画面まで進む。目標時刻まで待って確定する。移動・メニュー操作はこの時間に含まれる。
5. 外れた場合だけ実測投入Fを周辺表示で特定し、詳細設定に `次回の着弾補正F = 現在の補正F + 実測投入F − 目標投入F` を設定する（初回の補正Fは0）。次の試行では新しいコード1と録画の調合開始Fを使う。お守り生成Fをそのまま実測投入Fにしない。

コード2では、ケルビ納品クエストの受付嬢へRを押したまま `tiltLeftStick(Stick::MAX, Stick::MIN, 1500)` で移動する。

**予備コード3**はコード1後のHOME中断から再開し、指定時間だけアイテムボックス前で待機してから、登録済みのアイテムマイセットを呼び出して所持品を復元する。その後はコード1と同一の調合・録画・HOME操作を生成する。新しい録画から調合開始Fを再特定し、コード2の投入時刻を再計算する。古い調合開始Fとコード2の時刻は引き継がない。コード3に入力する箱メニュー位置、呼び出しメニュー位置、マイセット番号、確認A回数は実機の画面に合わせる。マイセット選択画面が直接開く場合は「呼出↓」を `-1` にして中間のA入力を省く。補充用素材と調合書を含み、Lv2通常弾が0個のマイセットを事前に登録しておく。

プーギー退避は、A→3秒待機→A→下1回→Aで「抱く」を決定する。下キーの操作は `pushHat(Hat::DOWN, 250)`。プーギーへ向かった左上とは逆の右下方向へ、原典の `(MAX, MAX, 2000)` で入口まで戻り、Aで退出する。入口で左上へ向き直す入力は行わない。退出後は2秒待ってAでペットを置き、`L（100, 5）→X（250）→A（250, 2）→3秒待機` でマップから自宅へ戻る。反応待ちの長さ、屋外で置く位置、再入室、ロード待ちは実機で確認・調整が必要。参照資料に公開されているのは移動座標と手順であり、生成したボタン列全体が原典の実機検証済みコードという意味ではない。調合はLv2通常弾0個から開始し、コード2用の投入護石3個とケルビの角を用意する。メニューと護石の初期カーソル位置も確認する。

コード2の時刻は**概算**。`復帰から投入までの目標時間 = (目標投入F − 調合開始F − 着弾補正F) ÷ 30 × 1000 − 9850` ms。9850msは使用するNintendoSwitchControlLibraryの既定の入力時間とコード1の調合開始→HOME押下までの操作から計算した値で、実機の乱数進行や入力認識の誤差は含めない。調合・HOME・錬金の操作を変えた場合は0から着弾を見直す。長時間の追加乱数消費は一定とは限らないため、初回命中は保証しない。Switchの自動スリープを無効にする。マイコンが再認識されない場合は、Switchで「コントローラー → 持ち方/順番を変える」を開き、コード2のL+R再接続オプションを使う。出入口、メニュー選択、移動距離は実機で確認・調整が必要。

Continue消費は常に一定の加算ではなく、直前の乱数位置に依存する。特に7500回以上の連打で約700F単位のズレが出た実機報告がある。Continue回数の線形近似は概算に使い、長距離では調合逆算で現在Fを再特定する。

初回のContinue回数は `floor(目標F ÷ 校正した1回消費F) − 5`（下限0）で概算する。未校正時の1回消費Fは717。前回コード1の回数と調合開始Fがある場合も同じ校正値を使い、その実測位置から次回回数を再計算して、投入に最低25秒とContinue約2回分の余裕を残す。校正値の小数部も保持し、次回起動時に復元する。回数が変わると古い測定Fを消去するので、新しい録画から必ず再特定する。校正後もContinue消費の揺らぎは残るため、実測によるFの特定は省略しない。

マイセットの具体的なボタン列は環境により異なるため、生成された操作列は実機で確認・調整する。

主画面の入力は目標F・Continue回数（自動概算可能）・調合開始F。詳細設定にはLv2弾までの↓数、ロード前待機、プーギー退避、任意の着弾補正F、再接続、予備コード3のマイセット設定がある。旧設定の実測オフセットは意味が異なるため引き継がない。

### 5. タイマー

#### ラップタイマー
- スペースキーで開始／ラップ記録
- Enterキーで停止＆記録
- Rキーでリセット
- ラップタイム・累計時間・フレーム換算を表示
- CSV保存対応

#### 目標時間設定
- 目標フレーム・基準フレームから所要時間を計算

#### マカ錬金カウントダウン（手動投入用）
Arduinoを使わず手動でマカ錬金のタイミングを取りたい時のカウントダウン機能。

- **待機時間 (ms)**: 待ちたい時間（調合スナイプの目標Fとの差分を転送して設定できる）
- **開始までの猶予 (秒)**: 準備時間
- **切り上げ (秒)**: 投入を少し早める時間
- **サウンド有効**: チェック時、残り10秒からビープ、終了時に強い音

### 6. Arduino（Continue連打法）

タイトル画面でContinue→キャンセルを連打して RNG を進めるシンプルな手法。調合スナイプより手軽だが、目標Fが大きい場合は時間がかかる。

**入力:**
- 目標フレーム
- 基本消費フレーム c（デフォルト 1,675）
- Continue1回の消費フレーム fc（デフォルト 714）
- 待機時間の範囲（5,000〜20,000ms など）

**出力:**
- 計算結果: Continue連打回数、端数待機ms、推定到達F、総所要時間
- Arduino スケッチ（コピー or `.ino` 保存）

#### 待機時間の補正
実測フレームと目標フレームのズレから、次回用の Continue回数 と 待機時間 を再計算する。

実機の実測値から fc_actual を逆算し、前回 nc 近傍で探索して、最も差分が小さい解を採用する設計。

**入力:**
- 目標フレーム、実測フレーム、Continue回数、前回の待機時間

**出力:**
- ズレ量（オーバー／不足）
- 補正後パラメータ（Continue回数、待機時間）
- 補正ログテーブル（CSV保存可）

### 7. 報酬逆算

クエスト報酬画面に表示されたアイテムの個数と並びから、現在のフレームを特定する。

調合スナイプでズレた時、「どのフレームで終わったのか」を逆算するのに使う。

**入力:**
- 報酬個数（4〜8個）
- 報酬アイテムリスト（複数可）
- 検索開始F・検索フレーム数
- 追加報酬閾値（なし=22、幸運=25、強運=28、激運=31）

**出力:**
- 報酬生成直前F
- 報酬生成による消費（4〜8個に対して5/7/9/11/12F）を加えた現在F
- 現在F時点のクエスト産お守り

### 8. キャリブレーション

実機の消費フレーム値（c, fc）を実測するための補助タブ。

校正対象は「調合Arduino（500ms周期）」と「Arduino（400ms周期）」から選ぶ。ステップ1でContinue 0回のコードから基本消費を求め、ステップ2で指定回数のコードを実行して実際の投入Fを入力し、「Continue消費を計算」を押す。選択した対象へ計算結果が自動反映される。調合Arduinoでは、その後に「Continue回数を概算」を押すと校正値で回数を計算する。

500ms用の校正コードはコード1と同じContinue操作を使う。400ms用の結果は500ms用に転用せず、別々に保存する。400ms用コードにある10秒の事前待機は校正計算で差し引く。基本消費cは校正用の錬金経路の値で、調合Arduinoの投入時刻には使わない。

### 9. 有名お守り

実用性の高いお守りのリストと生成Fを確認できる。旧リストで乱数計算と一致しなかった7件は除外し、記事で紹介された光る・古びたお守りの実例を追加した。全件マカ錬金のrank4で、種類欄の方式とともに当たりF数を表示する。ダブルクリックまたは右クリックの「周辺表示へジャンプ」で、種類・方式・投入ptを引き継げる。

## 設定の保存

ウィンドウを閉じる時に、実行ディレクトリの `mhxx_charm_settings.properties` に各種入力値が自動保存される。次回起動時に復元される。

**保存対象:**
- お守り検索: 種別・スロット・検索開始F・検索範囲・選択スキル・SP値
- 周辺表示: フレーム位置・お守り種別・原産地・前後範囲・錬金方式・投入合計pt
- 報酬逆算: 検索開始F・検索範囲・追加報酬閾値
- 調合スナイプ: 累積弾数・検索開始F・検索範囲・目標F・Continue回数・調合回数・Lv2↓数
- 調合Arduino: 調合開始F・目標F・500ms周期の校正済みContinue消費・着弾補正F
- キャリブレーション: 校正対象（調合Arduino / Arduino）
- 待機時間の補正: 目標F・実測F・Continue回数・前回の待機時間
- Arduino: c・fc・目標F
- ウィンドウ位置・サイズ
- 選択中タブ

## 補正計算ロジック（技術的補足）

ツールが目標到達するフレームを計算する基本式：

```
actual_frame = c + fc × nc + 0.030 × t2
```

- `c`: 基本消費フレーム（固定）
- `fc`: Continue1回あたりの消費フレーム
- `nc`: Continue連打回数
- `t2`: 端数待機時間（ms）
- `0.030`: 1msあたり0.03フレーム（30fps）

実機との誤差が出た場合、`fc_actual` を逆算してから再計算する：

```
fc_actual = (actual - c - 0.030 × prevT2) / prevNc
```

これを使って前回 `nc` 近傍から探索し、最小変更で目標到達できる解を採用する。
